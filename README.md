# qeuapps.com — Q Apps website

The official website for **Q Apps**, hosting information, tutorials, privacy
policies and support pages for our mobile apps (currently **Countdown Keeper**
and **Vault — Warranty Manager**).

- **Live site:** https://qeuapps.com (Cloudflare Pages)
- **Tech:** hand-written **static HTML5 + CSS3 + a little vanilla JavaScript**.
  No framework, no database, no backend. The pages are generated by a small
  dependency-free Python script and the generated output is committed.
- **Languages:** English (default) and Modern Standard **Arabic** with full RTL.
  Privacy policies are additionally published in up to 18 languages.
- **Privacy:** no cookies, no analytics, no third-party trackers.
- **Origin:** migrated from the Thiban Tech Solutions site
  ([AlmalawiCode/thiban1.com](https://github.com/AlmalawiCode/thiban1.com) @ `947ffda`).
  All URL paths (including every `/privacy/<app>/<lang>/` policy URL) are unchanged.

## Local preview

Any static file server works. From the repository root:

```bash
python3 -m http.server 8099
# then open http://127.0.0.1:8099/
```

> Use a server (not `file://`) because internal links are root-absolute
> (e.g. `/apps/`).

## How the site is generated

The published files (`index.html`, `apps/…`, `sitemap.xml`, …) are **plain
static output** and can be edited directly. To keep ~15 bilingual pages
consistent (shared header/footer, SEO/Open-Graph tags, the language switch),
they are produced from one small script:

```bash
python3 tools/build.py    # regenerates all *.html + sitemap.xml + robots.txt + site.webmanifest
```

`tools/build.py` needs only Python 3 (no packages). The **output** it writes has
no dependencies at all, which keeps the site portable.

Edit content in `tools/build.py` (or `content/privacy/<app>/<lang>.json` for
localized privacy policies) and re-run it — **don't hand-edit the generated
HTML**: Cloudflare Pages re-runs the builder on every deploy, so hand edits to
generated files are overwritten. The Vault campaign page (`/vault/`,
`/vault-new/`) is the one hand-tuned page; edit it in
`tools/templates/vault-campaign.html` and the builder copies it into place.

### Bilingual content

Every translatable string is emitted twice — `<... data-en>` and
`<... data-ar>` — and both ship in the HTML. CSS shows only the active
language based on `html[data-lang]`; `assets/js/site.js` toggles the language
(persisted in `localStorage`) and sets `dir="rtl"` for Arabic.

## Adding a new app

1. Copy the app's icon and 3–4 screenshots into `assets/img/apps/<slug>/`
   (copy the files — never reference another repository's path).
2. In `tools/build.py`, add an entry to the `APPS` dict (`name_en/ar`,
   `tagline_en/ar`, `icon`, `status` = `live` or `soon`, store URLs, `screens`).
3. Add page functions modelled on the existing ones:
   `page_app_<slug>`, `page_tutorial_<slug>`, `page_privacy_<slug>`,
   `page_support_<slug>`, and register them in `main()`.
4. Add the slug to `APP_ORDER` and a one-line tile text to `SHORT` in
   `tools/site_layout.py` — the home grid, `/apps/`, the app count and the footer
   all follow from it.
5. Run `python3 tools/build.py` and preview locally.

Only add a real, public store URL. If an app isn't released yet, set
`status: "soon"` (shows a subtle “Coming soon”) — never invent a store link.

## Adding / editing a tutorial

Edit the relevant `page_tutorial_<slug>` function: it takes a list of numbered
steps, tips, and FAQ entries, and an optional YouTube embed. Re-run the builder.

## Updating a privacy policy

Edit `page_privacy_<slug>` in `tools/build.py` (sections are `(id, heading_en,
heading_ar, html_en, html_ar)`), update the “Last updated” date passed at the
bottom of the function, and re-run the builder. Keep every statement accurate to
the app's actual behaviour.

## Deployment (Cloudflare Pages, GitHub integration)

Every push to `main` deploys automatically; pull requests / other branches get
preview URLs.

- Repository: https://github.com/AlmalawiCode/QApps
- Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git**
  → select `AlmalawiCode/QApps`, production branch `main`.

| Setting                | Value                     |
|------------------------|---------------------------|
| Framework preset       | **None**                  |
| Build command          | `python3 tools/build.py`  |
| Build output directory | `/` (repository root)     |
| Root directory         | *(empty)*                 |
| Environment variables  | none required             |

Cloudflare Pages serves `404.html` for unknown paths and `index.html` for
directory URLs, so no extra config is needed. There is intentionally **no**
`CNAME` / `.nojekyll` (GitHub Pages files) in this repository.

### Custom domain

In the Pages project → **Custom domains** → add `qeuapps.com` (and optionally
`www.qeuapps.com`). With the zone on Cloudflare, Cloudflare creates the DNS
records and the certificate itself. Do not point the domain at GitHub Pages.

### Backend API

The Vault campaign page calls the existing Cloudflare Worker at
**`https://api.thiban1.com/`** (proxy to the Apps Script backend), configured by
`VAULTNEW_API_BASE` in `tools/build.py`. The Worker answers CORS with
`Access-Control-Allow-Origin: *`, so it works unchanged from qeuapps.com.

## Contact & suggest (messages from visitors)

**Full owner's guide (Arabic): [`docs/feedback-system-guide-ar.html`](docs/feedback-system-guide-ar.html)** — tables and columns, how a message is saved and read, every Cloudflare setting, backups, and rebuilding from scratch.

Approved proposal: `proposals/qapps_feedback_proposal_ar.html` (website only; the
apps are unchanged). Visitors write on **`/suggest/`** (each app page links to it
with `?app=<slug>`); messages are saved in a **Cloudflare D1** database and read
by the owner on **`/admin/`**.

| Path | What |
|---|---|
| `functions/api/feedback.js` | `POST /api/feedback` — checks, Turnstile, rate limits, saves |
| `functions/api/admin/messages.js` | `GET`/`POST /api/admin/messages` — the dashboard's data (Access only) |
| `lib/feedback/` | shared rules + the Cloudflare Access token check |
| `migrations/0001_feedback.sql` | the tables (the API also creates them on first use) |
| `assets/js/suggest.js` | the form; falls back to WhatsApp/email if the system is not ready |
| `admin/index.html` | the owner's dashboard (hand-written, not generated) |

Protection: site-only origin, hidden honeypot field, minimum 2 s on the page,
field checks, **Turnstile**, 5 messages/hour and 10/day per visitor (salted
daily fingerprint of the address, deleted after 24 h), 300/day for the whole
site, and messages with more than 2 links are flagged. The admin API verifies
the **Cloudflare Access** token itself (signature, audience, issuer, expiry) and
fails closed. Until everything below is set, the form offers WhatsApp/email
instead, so nothing breaks.

### One-time setup (Cloudflare dashboard)

1. **Database** — Workers & Pages → D1 → *Create* → name `qapps-feedback`.
   Then the Pages project → Settings → Bindings → *Add* → D1 database,
   variable name **`DB`** → `qapps-feedback` (Production and Preview).
2. **Turnstile** — Turnstile → *Add widget* → hostnames `qeuapps.com`,
   `www.qeuapps.com`, mode *Managed*. Copy both keys.
3. **Variables** — Pages project → Settings → Variables and Secrets:
   - `TURNSTILE_SITE_KEY` = the site key (plain text; read by `tools/build.py` at build time)
   - `TURNSTILE_SECRET` = the secret key (*Encrypt*)
   - `IP_SALT` = any long random text (*Encrypt*), e.g. from `openssl rand -hex 32`
   - optional `DAILY_CAP` (default 300), `ALLOWED_ORIGINS` (default `https://qeuapps.com,https://www.qeuapps.com`)
4. **Protect the dashboard** — Zero Trust → Access → Applications → *Add* →
   Self-hosted: domain `qeuapps.com`, paths **`/admin`** and **`/api/admin`**;
   policy *Allow* → *Emails* → your email (login method: one-time PIN).
   Copy the application's **AUD tag**, and note your team domain
   (`<team>.cloudflareaccess.com`). Add Pages variables:
   `ACCESS_AUD` = the AUD tag, `ACCESS_TEAM_DOMAIN` = `<team>.cloudflareaccess.com`,
   optional `ADMIN_EMAILS` = your email.
5. **Redeploy** (push, or *Retry deployment*) so the build picks up the site key.
   Then open `qeuapps.com/suggest/`, send a test, and see it on `qeuapps.com/admin/`.

### Local test

```bash
npm i wrangler   # in any folder outside the site
TURNSTILE_SITE_KEY=1x00000000000000000000AA python3 tools/build.py
npx wrangler pages dev . --d1 DB=local --binding TURNSTILE_SECRET=1x0000000000000000000000000000000AA \
  --binding IP_SALT=test --binding ALLOWED_ORIGINS=http://127.0.0.1:8788 --binding ADMIN_DEV_BYPASS=1
python3 tools/build.py   # rebuild without the test key before committing
```
(`1x…AA` are Cloudflare's always-pass test keys. `ADMIN_DEV_BYPASS` works only on localhost.)

### Daily email summary (`workers/digest/`)

A separate Worker, **`qapps-digest`** (Pages Functions cannot run on a
schedule), runs every day at 05:00 UTC (08:00 Saudi time), reads the same D1
database and emails the owner the messages of the last 24 hours, with a link to
`/admin/`. Nothing is sent on a day with no new messages. It has no public URL.

- Mail goes out through **Cloudflare Email Routing** on `qeuapps.com`
  (`send_email` binding, from `digest@qeuapps.com`). It can only send to a
  *verified* destination address of the account.
- The recipient is the Worker secret **`DIGEST_TO`** (kept out of this public repo).
- Setup, once: Email → Email Routing on `qeuapps.com` → enable; add the
  destination address and click the verification email; then from
  `workers/digest/`: `npx wrangler deploy` and `npx wrangler secret put DIGEST_TO`.
- Local test: `npx wrangler dev --test-scheduled` with `DIGEST_TO` in
  `.dev.vars`, then open `/__scheduled` — the email is written to a local `.eml` file.
